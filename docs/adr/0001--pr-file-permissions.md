# 按 PR 作者限制文件范围

状态：implemented

## 问题

练习仓库允许学生提交个人介绍和网页，同时需要保护其他成员文件及仓库配置。维护者需要维护文档和工作流，不能套用学生的文件范围。

## 决策

以 GitHub 提供的 PR 作者用户名识别身份，仅 `mel0nyrame` 享有文件范围例外。具体文件范围由根目录 README 和 `members/README.md` 定义，检查入口为 `.github/scripts/check_pr.py`。

新增、删除和重命名都需要检查路径，防止删除或移动其他人的文件。检查脚本及其测试从受信任的默认分支运行，只读取 PR 的 Git 数据。`pull_request_target` 上下文不能执行 PR 中的脚本或网页，因为 PR 可以修改这些文件。

## 备选方案

- 自己文件夹内的附加文件仅作提示。该做法无法强制执行个人文件范围要求，因此采用明确的文件白名单。
- 所有人使用同一文件范围。该做法会阻止维护者维护 README 和工作流，因此仅为指定账号豁免文件范围，不豁免其他规范。

## 后果与风险

既有文件不会被批量清理，但非维护者不能通过 PR 改动白名单以外的文件。只更新网页时无需同时改动个人文本文件。

例外只授予固定用户名，不随 PR 的触发者或 commit 作者改变。账号更名时需要同步脚本与文档。PR 作者身份并不证明文件内容安全，仍需要人工审查。

分支检查保留 `add-用户名` 的兼容入口，避免已有学生 PR 仅因分支格式变化被阻止；新建分支推荐使用 `类型/内容`。

工作流规则更新需合并到默认分支后才生效，因此修改检查规则的 PR 仍由默认分支上的规则检查。回归测试覆盖文件范围、删除、重命名、文件类型、分支兼容和维护者例外，运行方式见根目录 README。
