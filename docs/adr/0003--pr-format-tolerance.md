# 放宽 PR 格式检查的分隔符

状态：implemented

## 问题

标题和 commit 要求 `<类型>: <说明>`。
中文输入法容易打出全角冒号，冒号后也容易漏掉空格。
只接受半角冒号加一个空格，会让只差一个不可见字符的 PR 失败。
检查允许中文说明，却只拦截英文无意义词，`docs: 测试` 可以通过，`docs:测试` 反而因格式失败。
README 要求 PR 目标分支是 `main`，脚本没有检查，规则和实现也不一致。

## 决策

冒号接受半角 `:` 和全角 `：`，冒号后的空格数量不限，包括制表符和全角空格。
类型仍限 `feat`、`fix`、`docs`、`chore`，说明仍为 2–50 个字符。
类型后的 scope、冒号前的空格继续拒绝；类型前加引号或反引号仍不符合格式。
无意义说明词表同时覆盖英文和中文，只拦截完全相等的说明，不做语义判断。
检查 PR 的目标分支是否为 `main`，与 README 的规则一致。

## 备选方案

- 继续只接受半角冒号加一个空格。两个已有 PR 仅因空格失败，所以不采用。
- 接受冒号前后的任意空白，或接受 `类型(scope):`。scope 不在课程规范内，冒号前的空格是可见错误，所以不采用。
- 继续只拦截英文无意义词。中文说明已经是一等公民，只拦英文会放行 `docs: 测试`，所以不采用。
- 用长度或模型判断说明是否有意义。检查必须离线、可重复、无额外依赖，词表足够覆盖当前的低质量提交，所以不采用。

## 后果与风险

两个已关闭的 PR 会因空格容错变为可通过。
开放 PR 通常还有文件范围、描述或 commit 问题，这项改动不会单独提高通过率。
词表是有限集合，`docs: 随便写` 仍会通过，需要人工审查补位。
目标分支检查目前没有发现违规 PR，它防止未来把 PR 提到 Fork 仓库的 `main` 或其他分支。
检查规则合并到默认分支后才生效，因此本 PR 仍由旧规则检查。
