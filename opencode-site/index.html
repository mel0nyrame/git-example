把 AI 放进终端，

OpenCode 是一个开源、厂商中立的 AI 编码代理。它在终端、桌面应用、IDE 和浏览器里， 用你指定的任意模型读仓库、改文件、跑命令、查文档——不把你绑在任何一家模型商身上。

01 / 定位

它不是一个补全插件，
而是一个能自己动手的代理

补全工具预测你的下一行；代理则接受一个目标，自己决定读哪些文件、跑哪些命令、改哪几行， 过程中把关键动作交给你确认。

你在项目目录里敲下 opencode，得到的是一个全屏终端界面：左边是对话，右边是文件与 diff， 下方是输入框。它可以按 @ 模糊搜索仓库里的文件、自动加载对应的语言服务器、 在改动前先给出计划，在改动后展示逐文件的差异。

更关键的是它的取舍——不绑定模型厂商。通过 Models.dev 接 75+ 提供商， 也能复用你已有的 GitHub Copilot 或 ChatGPT Plus/Pro 订阅，甚至接本地 Ollama。 如果懒得挑，官方还有经过实测筛选的 Zen 模型集与每月 10 美元的 Go 订阅。

代码层面它完全开源（MIT），仓库公开、可审计、可 fork。官方声明不存储你的代码与上下文数据 （使用官方免费模型时除外），因此也被用在隐私敏感的环境里。对合规有要求的团队，还有企业版。

值得单独一提的是它的客户端 / 服务端架构：TUI 只是一个客户端， 背后是一个本地 HTTP 服务，暴露 OpenAPI 3.1 与 SSE 事件流。这件事决定了后面所有的可扩展性。

02 / 能力

八件它做得很到位的事

从模型接入到会话回滚，这些设计共同指向同一个目标：让代理的行为可预期、可控制、可复现。

终端优先，多端同源

核心体验是终端里的全屏 TUI，同时提供桌面应用、IDE 扩展和 Web 界面。它们连的是同一个本地服务，会话与配置共用。

任意模型，厂商中立

75+ 提供商、本地模型、Copilot 与 ChatGPT 订阅都能接；官方 Zen 提供实测过的精选模型，Go 订阅按月打包主流编码模型。

LSP 加持的代码理解

自动加载项目对应的语言服务器：跳转定义、符号搜索、实时诊断都交给真正的语言工具，而不是让模型猜。

计划先行

按 Tab 在 Plan / Build 之间切换。Plan 模式下它只出方案、不动文件——先对齐思路，再让它动手。

随时反悔

/undo 与 /redo 按消息粒度回滚改动，配合会话级 diff，试错的成本被压得很低。

会话可分享

把一次排障过程分享成链接，队友能直接看到完整的上下文与工具调用，复现问题不用靠转述。

客户端 / 服务端架构

opencode serve 暴露 OpenAPI 3.1 与 SSE；SDK 可把代理嵌进 CI、脚本或你自己的产品里。

隐私与可控

开源可审计，官方称不存储代码与上下文；权限确认、Policies、企业版让团队能收紧边界。

03 / 架构

界面只是客户端，
会话活在一个本地服务里

运行 opencode 时，它同时启动 TUI 和一个本地 HTTP 服务；同一个服务可以被 IDE 插件、桌面端、 浏览器甚至你的脚本连接。

TUI 桌面端 IDE 插件 Web / 脚本
HTTP · OpenAPI 3.1 · SSE 事件流
opencode server 会话 · 权限 · 工具执行 · 配置
模型调用 / LSP / MCP / 文件系统
75+ 模型提供商 LSP 语言服务 MCP 服务器 Git · Shell · 测试

为什么这个架构重要

多数同类工具把界面和逻辑焊死在一起，你只能在它规定的那个窗口里用它。 OpenCode 把「代理运行时」抽成一个可寻址的服务之后，很多事情就自然成立了：

  • 在终端里开一个会话，用 IDE 插件接着看同一份上下文；
  • 服务器上 opencode serve 跑无头实例，用 SDK 批量跑任务；
  • 用 /tui 系列端点从外部驱动界面，IDE 插件就是这么做的；
  • 把 service 关掉、用 --standalone 起私有实例，或 --server 连到指定地址。

默认情况下，OpenCode 会为你的账户发现或启动一个共享后台服务， 所有本地客户端都连它，会话、集成、权限与工具执行都归属于它。 

# 无头服务（默认 4096 端口）
opencode serve --port 4096

# 生成 OpenAPI 3.1 规范 / Swagger 页面
open http://localhost:4096/doc

# 私有实例，不加入共享服务
opencode --standalone

04 / 上手

五分钟，从安装到第一次改动

你只需要一个现代终端，和一个模型提供商的 API Key（或直接用内置免费模型）。

  1. 1

    安装

    macOS / Linux 用安装脚本最快；macOS 也可以用 Homebrew 的官方 tap 拿到最新版本。

    $ curl -fsSL https://opencode.ai/v2/install | bash
# 或
$ brew install anomalyco/tap/opencode
  2. 2

    连接模型

    进入项目目录，运行 opencode，然后在输入框里输入 /connect，选择提供商并粘贴 Key。想省事就选 opencode（Zen），它是团队实测过的模型集合。

    $ cd ~/code/my-project
$ opencode
# TUI 内：
/connect
  3. 3

    让它认识你的项目

    /init 会扫描仓库并在根目录生成 AGENTS.md，把结构、规范、常用命令记下来。建议把它提交进 Git。

    /init
# → 生成 AGENTS.md，随项目一起版本管理
  4. 4

    先计划，再动手

    按 Tab 切到 Plan 模式，把需求和约束讲清楚（像对新同事交代任务）；满意后按 Tab 切回 Build 模式，让它实施。

    # Plan 模式
给 /settings 路由加上鉴权，参考 @packages/functions/src/notes.ts 的做法

# 确认计划后切到 Build
按这个计划实施，并补上 401 的集成测试
  5. 5

    不满意就回滚

    改动不对味，/undo 回到上一步并保留你的原始输入，改改提示词再来一次；/redo 可以重做。

05 / 速查

常用命令与快捷键

记住这几条，日常使用基本够用。

OpenCode 常用命令与快捷键
命令 / 快捷键作用
opencode在当前目录打开全屏终端界面（同时启动本地服务）

/undo · /redo按消息回滚或重做改动
Tab在 Plan 与 Build 模式之间切换
@模糊搜索项目文件并加入提示词
拖拽图片把设计稿或报错截图放进终端作为参考

06 / 适合谁

它更像给这几类人准备的

终端原住民

你的工作流本来就在 shell 里：git、测试、日志、ssh。你不想为了用 AI 再开一个 IDE 或网页。

模型尝鲜者

你想随时换模型、跑对比、试本地模型，而不希望工具把你的选择锁死。

隐私敏感团队

需要可审计的开源实现、明确的权限边界，甚至自托管与无头部署。

做集成的人

想把编码代理嵌进 CI、内部平台或自研客户端——OpenAPI 与 SDK 就是入口。

如果完全不想碰命令行，也不需要自定义模型，那么成熟的商业 IDE 方案可能更省心——OpenCode 的收益主要来自「终端 + 自选模型 + 可扩展」这三件事。

07 / 生态

不只是一个命令行工具

Zen

模型

经过 OpenCode 团队实测与基准筛选的编码模型集合，省去「哪个提供商效果稳定」的试错；也提供内置免费模型。

Go

订阅

每月 10 美元的订阅方案，打包主流编码模型的使用额度，适合不想分别管理多家 API Key 的个人开发者。

扩展体系

可编程

MCP 服务器、插件、自定义命令、Agent 技能、权限策略、自定义工具与 SDK——团队可以把它捏成自己的形状。

企业版

合规

面向需要审计、访问控制与私有部署的组织，配合 OPENCODE_SERVER_PASSWORD 等机制保护服务端。

08 / 问答

几个常见问题

OpenCode 收费吗？

软件本身免费且开源（MIT）。模型部分：内置一组免费模型，无需账号即可使用；也可以自备各家 API Key，或订阅 Zen / Go。费用来自模型推理，而不是工具本身。

必须使用某一家的模型吗？

不需要。它通过 Models.dev 支持 75+ 提供商，包括 Claude、GPT、Gemini 以及本地模型；也能直接登录 GitHub Copilot 或 ChatGPT Plus/Pro 复用已有订阅。

我的代码会被上传吗？

代码只会发送给你选择的模型提供商。官方声明 OpenCode 本身不存储代码与上下文数据，但使用官方免费模型时会遵循对应的数据政策。隐私要求高的场景建议自备 Key 或使用企业版。

Windows 能用吗？

可以。v2 提供 Windows 独立二进制（x64 / ARM64），但暂不通过 Windows 包管理器分发；官方推荐在 WSL 里使用以获得完整体验。v1 时代还支持 Chocolatey / Scoop。

和 Claude Code、Cursor 是什么关系？

它们是各自独立的商业产品，定位也不同：Cursor 是编辑器，Claude Code 绑定 Anthropic 模型。OpenCode 的差异在于开源、模型中立、以及面向终端的客户端/服务端架构。三者可以并存，甚至可以同时用。

v1 和 v2 该装哪个？

新项目直接用 v2。两者共用 opencode 命令、默认不能并存，安装脚本地址也不一样（v2 为 https://opencode.ai/v2/install）。从 v1 迁移前请先读官方迁移指南。

需要什么基础？

会用终端（cd、git 基本操作）就够了。真正的门槛不在工具，而在于能否把需求讲清楚——它更像个执行力很强但需要上下文的同事。
